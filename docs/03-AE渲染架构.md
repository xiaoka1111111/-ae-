# 03 · AE 渲染架构

本文解答插件如何接入 After Effects 渲染管线：渲染路径、坐标系、区域渲染、
缓存行为、多线程与关键标志位。

---

## 1. 渲染路径选择：传统 Render vs SmartRender

AE 效果插件有两条渲染路径：

| | 传统 Render（本项目使用） | SmartRender |
|---|---|---|
| 命令 | `PF_Cmd_RENDER` | `PF_Cmd_SMART_PRE_RENDER` + `PF_Cmd_SMART_RENDER` |
| 世界 | src == output == 图层像素尺寸 | 可请求任意区域（变换后区域）|
| 标志 | 不设 `PF_OutFlag2_SUPPORTS_SMART_RENDER` | 设置该标志 |

本项目**固定传统路径**（`out_flags2 = 0`）：

- 传统路径下 AE 保证 src 与 output 同尺寸同原点，坐标处理简单可靠
- 复刻的左上对齐在 SmartRender 的区域渲染下会把内容偏移到 (0,0)，
  故不声明 SmartRender 支持（连带不设 FLOAT_COLOR_AWARE，AE 严格校验两者绑定）

## 2. 世界坐标系

```
PF_EffectWorld: width/height/origin_x/origin_y/extent_hint/rowbytes/data
```

- **传统 Render**：`src->origin == output->origin`，内容位于世界左上
- **矢量文字层**在合成分辨率下渲染时，world = 合成尺寸
  （如 4000×4000），图层内容 = extent_hint 包围盒
- **区域渲染**：只读 `extent_hint` 有效矩形，区域外数据不保证有效

### 本项目的处理

1. `copyToFloat`：源世界 → 浮点缓冲（输出世界尺寸），按
   `(src.origin − out.origin)` 偏移放置，只拷 extent 有效区
2. 渲染区域 = `extent + 偏移`，钳制到世界边界；区域外不渲染
3. 种子锚定到**内容包围盒**（区域），与图层在合成中的位置无关
   （详见原理篇 §7-2）
4. `copyFromFloat`：结果写回输出世界

## 3. 时间与帧

```
current_time : A_long（帧时间，单位 = time_scale 的分数）
time_scale   : A_u_long（每秒 tick 数，如 30fps → 30720）
seconds      = current_time / time_scale
```

- 进度映射与循环折叠见原理篇 §3.1
- **注意**：不要混淆 `in_data->time_step`（步长）与 `current_time`

## 4. 关键全局标志（GLOBAL_SETUP）

| 标志 | 本项目 | 含义 |
|---|---|---|
| `PF_OutFlag_PIX_INDEPENDENT` | ✓ | 输出与像素格式无关（可跨位深）|
| `PF_OutFlag_DEEP_COLOR_AWARE` | ✓ | 支持 8/16/32bpc |
| `PF_OutFlag_NON_PARAM_VARY` | ✓ | **输出依赖时间等参数之外的信息 → AE 逐帧重渲** |
| `PF_OutFlag2_*` | 全不设 | 传统路径 |

### NON_PARAM_VARY 详解（踩坑记录）

SDK 原文："Set this if the effect uses information **other than the parameters**
to generate its output at the current time. For instance, if the effect **uses
the current time of the frame**..."

- **设置** = 声明输出随时间变化 → AE 每帧重渲、不跨时间缓存
- **不设置** = AE 认为"参数不变则输出不变" → 参数无关键帧时跨时间只渲一帧并复用

不设置该标志的典型症状（本项目实测踩过）：

- 播放/拖动时间线**没有动画**（所有帧显示同一帧）
- **只有拖动图层**（输入变化 → 强制重渲）才刷新画面
- 渲染队列（RQ）逐帧强制渲染，不受影响——所以"探针正常、交互无动画"

> 该标志的语义极易与直觉相反：名字叫 NON_PARAM_VARY，行为却是"告诉 AE
> 输出不依赖参数（依赖时间）"。实现时间驱动效果时**必须设置**。

## 5. 缓存行为

AE 的磁盘/GPU 缓存键包含：图层内容、效果参数布局（ECW）、时间、分辨率等。
**实测不包含插件版本号与参数布局变化**（同一效果的旧版本帧会继续命中缓存）。

影响与对策：

1. **升级插件后旧帧残留**：表现为"装了新版本画面没变化"。
   对策：变更效果 matchName（全新效果身份）或清理缓存
   （编辑 → 清理 → 所有内存与磁盘缓存）。
2. **效果身份变更**：matchName 变化后，旧工程中的效果实例变为"丢失"，
   需删除旧效果重新添加（新实例 = 新缓存键，无需清缓存）。

## 6. 多线程渲染

AE 会并行渲染多个帧/区域（不同线程同时进入 `PF_Cmd_RENDER`）。

本项目线程安全设计：

- 进程级缓存（距离场/静态场）用 `std::mutex` 保护，缓存值按值拷贝
- 无跨帧共享可变状态（每帧局部缓冲）
- 日志写入用互斥锁 + 单文件追加

## 7. 调试手段

- **插件日志**：`%TEMP%\TestFill_debug.log`（每帧记录时间/进度/种子/输出统计，
  上限 8MB 自动截断）——判断"AE 是否在逐帧调用插件"的最直接证据：
  播放几秒，日志中应出现几十行 `[time] sec=` 递增记录
- **无头渲染探针**：AE 2026 可用 `AfterFX.exe -r script.jsx` 驱动
  （RenderQueue 渲染、`saveFrameToPng` 等）验证算法正确性
